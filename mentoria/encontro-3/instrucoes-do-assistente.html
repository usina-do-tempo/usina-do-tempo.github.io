Instruções do Assistente

Mentoria Regente — material do participante · Realização: Usina do Tempo Marketing Ltda.

As instruções permanentes do seu assistente

Preencha os campos abaixo uma única vez — é este texto que vai morar no espaço de trabalho da sua ferramenta (o que ela chamar de Projeto, Habilidade, Espaço ou GPT: o campo onde se colam instruções que valem para toda execução futura, não só para a conversa de hoje). Depois de colado, você não digita isto de novo — só preenche as lacunas do pedido do dia.

Modelo para preencher

FUNÇÃO: [o que este assistente faz, numa frase — a tarefa específica dele, não "me
ajude com tudo"]

Erro comum: escrever uma função larga demais (“me ajude com o atendimento”) em vez de uma tarefa específica (“responda reclamações de atraso na entrega”). Assistente largo não cabe numa lista de qualidade curta — e você vai perceber isso só quando a resposta sair torta.

TOM: [como toda resposta deste assistente deve soar]

Erro comum: copiar o tom do pedido de um dia específico e tratar como se fosse o tom da tarefa inteira — um dia mais informal “contamina” todas as execuções seguintes.

QUALIDADE (o que precisa aparecer sempre): [os 3 a 5 critérios que valem para TODA
execução desta tarefa — não para o caso de hoje]

Erro comum: colocar aqui um critério que só vale para o caso de hoje (“mencione o prazo de 6 dias”) — isso é variável, pertence ao pedido do dia, não às instruções permanentes.

NUNCA FAZER: [as duas ou três coisas que este assistente não deve fazer, mesmo se
pedido]

Erro comum: deixar este campo em branco por parecer óbvio — é justamente o campo que evita o erro mais caro (prometer prazo não confirmado, oferecer desconto sem limite, inventar um número que não existe).

DOCUMENTOS DE REFERÊNCIA: [quais documentos moram aqui — modelo de resposta,
glossário, tabela de preços — e uma linha do que cada um serve]

Erro comum: subir um documento e não dizer para que ele serve — o assistente usa documentos soltos pior do que documentos com uma linha de contexto.

ÚLTIMA REVISÃO: [data de hoje]

Erro comum: deixar este campo sem valor, ou esquecer de atualizá-lo quando o padrão do trabalho muda — instrução sem data de revisão é instrução que ninguém audita.

Exemplo preenchido — Empresa Alfa

FUNÇÃO: Ajudar o atendimento da Empresa Alfa a responder e-mails de clientes que
reclamam de atraso na entrega.

TOM: Cordial e resolutivo, sem ser subserviente — reconhece o problema sem exagerar no
pedido de desculpas.

QUALIDADE (o que precisa aparecer sempre): reconhecimento claro do atraso; nenhuma
promessa de prazo que não esteja confirmado no pedido do dia; a compensação (quando
houver) mencionada com destaque; no máximo 8 linhas.

NUNCA FAZER: nunca confirmar uma nova data de entrega sem que ela venha informada no
pedido do dia; nunca oferecer desconto acima de 15% sem que isso seja pedido
explicitamente; nunca inventar número de rastreio ou protocolo.

DOCUMENTOS DE REFERÊNCIA: modelo de e-mail padrão da Alfa (o formato e o tom que toda
resposta deve seguir); glossário de termos internos (para que "prazo combinado" e
"pendência de estoque" sejam usados do jeito certo).

ÚLTIMA REVISÃO: 06/09/2026

Checklist de 30 segundos antes de colar

  1. Cada campo descreve algo que vale para toda execução — nenhum deles descreve só o caso de hoje?
  2. O campo “nunca fazer” tem pelo menos uma linha — nenhum assistente sério fica sem ele?
  3. Cada documento de referência tem uma linha dizendo para que serve?
  4. A data de revisão está preenchida com a data de hoje?
